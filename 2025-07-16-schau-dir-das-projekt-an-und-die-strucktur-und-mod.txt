● Das ist ein Django-basiertes Kommunikationssystem für Wohnheime. Hier ist die Analyse:

  Projektstruktur

  - Django-Monolith mit 4 Haupt-Apps
  - PostgreSQL Datenbank mit Docker-Setup
  - WebSocket-Chat über Django Channels
  - Internationalisierung (DE/EN/RU/TR)

  Kernmodelle

  - CustomUser: Erweiterte User-Modell mit Rollen (Inactive → Admin), Themes, Bio
  - Chat/Message: UUID-basiert, Many-to-Many User-Beziehungen
  - Room: Wohnheimzimmer-Verwaltung
  - EmailVerification: Separate Email-Verifikation

  Hauptfeatures

  - Authentifizierung: Login/Register mit Email-Verifikation
  - Echtzeit-Chat: WebSocket-basiert mit Typing-Indikatoren
  - Theming: 11 verschiedene Themes (Light/Dark)
  - Rollenbasierte Zugriffe: 6 Rollen-Stufen
  - Zimmer-Auswahl: Room-Management für Wohnheime
  - Responsive Design: Mobile-optimiert

  Technologie-Stack

  - Django 5.2 + DRF
  - Channels für WebSockets
  - PostgreSQL + Redis
  - jQuery für Frontend
  - Docker + nginx

  Für Next.js Rebuild

  Das System ist gut strukturiert für eine moderne Neuimplementierung mit:
  - Next.js 14 mit App Router
  - WebSocket (Socket.io)
  - Tailwind CSS für Styling
  - Prisma für Datenbankzugriff
  - NextAuth.js für Authentifizierung

● Bei der Registrierung gibt es einen mehrstufigen Verifikationsprozess:

  Besonderheiten der Registrierung:

  1. Strenge Passwort-Anforderungen

  - Mindestens 16 Zeichen lang
  - Großbuchstaben, Ziffern und Sonderzeichen erforderlich
  - Regex-Validierung für alle Kriterien

  2. Zwei separate Zustimmungen

  - Terms of Service (AGB)
  - Privacy Policy (Datenschutz)
  - Beide müssen explizit bestätigt werden

  3. Mehrstufiger Verifikationsprozess nach Registrierung:

  Schritt 1: Email-Verifikation
  - Automatische Email mit UUID-Code
  - Kann per URL-Link oder manueller Eingabe verifiziert werden
  - Redirect zu account:email_verification

  Schritt 2: Zimmer-Auswahl
  - Nach Email-Verifikation → room:select_room
  - User muss einem Wohnheimzimmer zugeordnet werden
  - Mixin NoRoomRequiredMixin stellt sicher, dass nur Nutzer ohne Zimmer zugreifen können

  Schritt 3: Tenant-Verifikation
  - Nach Zimmer-Auswahl → account:verify
  - Zusätzlicher Verifikationscode (10 Zeichen) für Wohnheimbestätigung
  - Rollenupgrade von USER zu VERIFIED
  - Mixin RoomRequiredMixin stellt sicher, dass Nutzer bereits einem Zimmer zugeordnet sind

  4. Rollenbasierte Weiterleitung

  - Neue User starten mit Rolle USER
  - Erst nach beiden Verifikationen → VERIFIED
  - Nur VERIFIED User können die Homepage nutzen

  5. Automatischer Login

  - User wird direkt nach Registrierung eingeloggt
  - Flow leitet durch alle Verifikationsschritte

  Das System stellt sicher, dass nur verifizierte Wohnheimbewohner Zugang zur Plattform haben - eine wichtige Sicherheitsmaßnahme für das Uni-Umfeld.
